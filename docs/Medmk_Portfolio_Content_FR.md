# 4. Méthode de travail

**Surtitre**  
Méthode

**Titre principal**  
Comprendre le processus avant de développer la solution

**Introduction**  
Un bon projet d’automatisation commence rarement par le choix d’un outil. Il commence par comprendre ce qui se passe aujourd’hui, ce qui pose problème et ce qui doit réellement changer.

## 1. Comprendre le fonctionnement actuel

Nous partons du processus existant :
- quelles informations entrent ;
- qui intervient ;
- quelles opérations sont manuelles ;
- quels outils sont utilisés ;
- où apparaissent les erreurs, attentes ou doubles saisies.

## 2. Définir le résultat attendu

Nous précisons ce qui doit être amélioré avant de parler de technologie.

L’objectif peut être, par exemple :
- supprimer une ressaisie ;
- synchroniser deux systèmes ;
- automatiser un contrôle ;
- centraliser certaines informations ;
- rendre un traitement plus fiable.

## 3. Concevoir une solution proportionnée

Je privilégie le chemin le plus simple permettant de résoudre correctement le problème.

Selon le besoin, cela peut être :
- un script automatisé ;
- une intégration API ;
- un traitement de données ;
- une interface web ;
- ou une combinaison limitée de plusieurs éléments.

## 4. Gérer les erreurs et les exceptions

Un processus automatisé doit également prévoir ce qui arrive lorsque tout ne se déroule pas comme prévu.

Je prends notamment en compte :
- validations ;
- données manquantes ou incohérentes ;
- erreurs techniques ;
- tentatives de reprise lorsque cela est pertinent ;
- intervention humaine lorsqu’elle reste nécessaire.

## 5. Vérifier avant de généraliser

La solution est testée sur des scénarios réalistes avant d’étendre son utilisation.

Lorsque c’est possible, je privilégie une première version limitée permettant de vérifier rapidement que le fonctionnement répond réellement au besoin.
